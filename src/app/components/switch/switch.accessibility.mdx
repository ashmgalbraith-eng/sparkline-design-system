# Accessibility

## Role and ARIA

Switch should use `role="switch"` with `aria-checked` reflecting its on/off state:

- `aria-checked="true"` when the switch is on.
- `aria-checked="false"` when the switch is off.
- `aria-disabled="true"` when `disabled` is `true`.
- `tabindex="0"` when enabled; `tabindex="-1"` when disabled.

Pair the switch with a visible text label. If no visible label is possible, supply `aria-label` or `aria-labelledby` on the host element. The label should describe the feature being toggled, not just the current state (e.g. "Email notifications", not "On").

## Keyboard navigation

| Key | Behaviour |
|-----|-----------|
| `Tab` | Moves focus to the switch (skipped when disabled). |
| `Space` | Toggles the switch between on and off. |

## WCAG compliance

| Criterion | Level | Notes |
|-----------|-------|-------|
| 1.3.1 Info and Relationships | A | `role="switch"` with `aria-checked` communicates state programmatically. |
| 1.4.1 Use of Colour | A | On/off state is conveyed by position and colour — supplement with text or `aria-checked` for users who cannot distinguish colour. |
| 1.4.3 Contrast | AA | Thumb and track meet minimum contrast ratios in both on and off states. |
| 2.1.1 Keyboard | A | Togglable via `Space`. |
| 2.4.7 Focus Visible | AA | A visible focus indicator is shown on keyboard focus. |
| 3.3.2 Labels or Instructions | A | Always provide a descriptive label so users understand what the switch controls. |
| 4.1.2 Name, Role, Value | AA | Use `role="switch"`, `aria-checked`, `aria-disabled`; provide an accessible name via label or `aria-label`. |
