# Accessibility

## Role and ARIA

The host element uses `role="radio"` with the following attributes managed automatically:

- `aria-checked="true"` when selected, `aria-checked="false"` when not selected.
- `aria-disabled="true"` when `disabled` is `true`.
- `tabindex="0"` when enabled; `tabindex="-1"` when disabled.

Always group radio buttons inside a `<fieldset>` and `<legend>` (or `role="radiogroup"` with `aria-labelledby`) so assistive technology announces the group label before individual options.

## Keyboard navigation

| Key | Behaviour |
|-----|-----------|
| `Tab` | Moves focus to the selected radio in the group (or the first if none selected). |
| `Arrow Up` / `Arrow Left` | Moves to and selects the previous radio in the group. |
| `Arrow Down` / `Arrow Right` | Moves to and selects the next radio in the group. |
| `Space` | Selects the currently focused radio if it is not already selected. |

Arrow key navigation within the group should be implemented at the application or group-wrapper level using a roving tabindex pattern.

## WCAG compliance

| Criterion | Level | Notes |
|-----------|-------|-------|
| 1.3.1 Info and Relationships | A | Use `role="radiogroup"` with `aria-labelledby` or `<fieldset>`/`<legend>` to convey grouping. |
| 1.4.3 Contrast | AA | Label text and control boundaries meet minimum contrast ratios. |
| 2.1.1 Keyboard | A | Selectable via `Space`; arrow-key navigation within the group is the conventional pattern. |
| 2.4.7 Focus Visible | AA | A visible focus ring is displayed on keyboard focus. |
| 4.1.2 Name, Role, Value | AA | `role="radio"`, `aria-checked`, and `aria-disabled` are managed automatically. |
